<objective>
Install @sentry/react-native and add granular ErrorBoundary wrappers to each main tab and the critical ventas components so crashes are captured in Sentry and every screen shows a recovery UI instead of going blank.

Purpose: Without this, a runtime error in any tab silently blanks the screen — the user has no recovery path and the developer has no visibility. This plan adds both the monitoring (Sentry) and the recovery UI (per-tab ErrorBoundaries plus granular boundaries on CartPanel and ProductListContent).

Output: Sentry initialized in app/\_layout.tsx, @sentry/react-native/expo plugin registered in app.config.js, ErrorBoundary wrappers around ventas/productos/history/resumen tabs, and granular ErrorBoundary wrappers on CartPanel and ProductListContent.
</objective>

  <name>Task 1: Install @sentry/react-native and configure app.config.js with DSN env var</name>
  <files>app.config.js, app/_layout.tsx</files>
  <action>
    1. Install @sentry/react-native:
       ```
       npx expo install @sentry/react-native
       ```
       This runs Sentry's postinstall which may patch metro.config.js. Let it run.

    2. Convert app.json to app.config.js if it hasn't been done yet:
       - Read the existing app.json content
       - Create app.config.js that wraps the same config:
         ```js
         export default ({ config }) => ({
           ...config,
           plugins: [
             ...(config.plugins ?? []),
             ["@sentry/react-native/expo", { organization: "la-pape", project: "la-pape" }],
           ],
         });
         ```
       - If app.json already has a plugins array, merge rather than duplicate
       - Delete app.json after creating app.config.js (Expo reads app.config.js preferentially)

    3. Add EXPO_PUBLIC_SENTRY_DSN to .env.example (create if it doesn't exist):
       ```
       EXPO_PUBLIC_SENTRY_DSN=https://your-dsn@oXXXXXX.ingest.sentry.io/XXXXXXX
       ```
       Do NOT add the actual DSN — the user will fill this in. The plan's user_setup section documents where to find it.

    4. Update app/_layout.tsx:
       - Add import: `import * as Sentry from "@sentry/react-native";`
       - Add Sentry.init() call at the top of the file (outside the component, after imports):
         ```tsx
         Sentry.init({
           dsn: process.env.EXPO_PUBLIC_SENTRY_DSN,
           environment: __DEV__ ? "development" : "production",
           // Disabled in dev to avoid noise — enable temporarily to verify DSN is correct
           enabled: !__DEV__,
           tracesSampleRate: 0.2,
         });
         ```
       - Update the existing root ErrorBoundary onError to also call Sentry:
         ```tsx
         <ErrorBoundary
           onError={(error, info) => {
             logger.error("Layout error", { error: error.message, stack: info.componentStack });
             Sentry.captureException(error, { extra: { componentStack: info.componentStack } });
           }}
         >
         ```
         Keep the logger.error call — add Sentry alongside it, do not replace.

  </action>

  </verify>

  <action>
    For each of the four tab layout files, wrap the existing Stack (or root View/component) with an ErrorBoundary that captures to Sentry.

    Pattern to apply to each tab _layout.tsx:
    ```tsx
    import { ErrorBoundary } from "@/components/ui/ErrorBoundary";
    import * as Sentry from "@sentry/react-native";
    // ... existing imports ...

    export default function TabNameLayout() {
      // ... existing role guards or auth checks ...

      return (
        <ErrorBoundary
          onError={(error) => Sentry.captureException(error)}
        >
          <Stack screenOptions={{ headerShown: false }} />
          {/* or whatever the existing content is */}
        </ErrorBoundary>
      );
    }
    ```

    Rules:
    - If a tab _layout.tsx does not exist yet, create it with just the ErrorBoundary + Stack
    - If it already has an ErrorBoundary, add the Sentry onError prop — do not double-wrap
    - Place ErrorBoundary as the outermost wrapper (inside any auth/role guards that return early, since those are not errors — they're expected states)
    - For tabs that will get role guards in Plan 04, ErrorBoundary wraps the conditional render:
      the role guard returning <SinPermiso /> is NOT an error — keep ErrorBoundary outside the guard

    Read each file before editing to avoid overwriting existing content. Each tab's Stack config (screenOptions, routes) must be preserved exactly.
